# 기술 설명

대상: PS2 북미판 MLB 07: The Show v2.00 (SCUS-97556), 실행파일 `SCUS_975.56`.

## 디스크 구성

게임 데이터는 대부분 `MLBPS2.WAD`(LBA 14661) 하나에 들어 있습니다.

- 머리: 항목 수, 첫 데이터 오프셋. 이어서 항목마다 12바이트(경로 해시, 크기, WAD 시작 기준 오프셋)이며 해시 순으로 정렬돼 있습니다. 원본은 7,389개입니다.
- 경로 해시는 `h = h * 131 + c`(부호 있는 바이트)입니다. 경로는 앞의 `.`·`\`·`/`를 떼고, 대문자로 바꾸고, `/`를 `\`로 바꾼 뒤 계산합니다.
- 오프셋은 부호 있는 32비트로 다뤄져 WAD 시작에서 2GB 안쪽만 닿습니다.

`tools/build.py`는 다음처럼 배치합니다.

1. WAD 바로 뒤의 `SNDPS2/SOUND/FEPXP.SKX`를 ISO 끝으로 옮겨, WAD 오프셋으로 닿는 빈 영역을 만듭니다.
2. 바뀐 WAD 파일을 그 영역에 쓰고 디렉터리 항목의 크기·오프셋을 고칩니다.
3. ISO9660 디렉터리와 UDF 파일 항목을 고칩니다(`tools/isoedit.py`).
4. 크기가 같은 게임 모듈(REL)은 제자리에 덮어씁니다.

결과 ISO는 원본보다 FEPXP.SKX 크기만큼 깁니다.

### 해시의 대문자 변환

게임의 대문자 변환은 `ctype` 표(`0x199A61`)를 **부호 있는 바이트**로 참조합니다. 0x80 이상 바이트는 표 앞쪽 128바이트(관계없는 데이터)를 읽게 되고, 거기서 소문자 비트(2)가 켜진 값이면 0x20을 뺍니다. 그래서 한글 바이트가 들어간 경로는 단순 대문자화와 해시가 다릅니다. `tools/wadfs.py`는 실행파일의 그 표를 읽어 게임과 똑같이 계산합니다. 이것을 모르고 계산하면 아래 머리 별칭이 하나도 맞지 않습니다.

## 게임 모듈(REL)

FE(메뉴), GAME(경기), HRDERBY(홈런 더비), GHOSTMAN 모듈은 `SNR1` 재배치 모듈입니다. 머리 뒤에 재배치 표(위치, 종류, 대상)와 심볼 표가 있습니다(`tools/snr.py`).

**모듈 크기를 바꾸면 메모리 배치가 깨져 멈추므로** 크기를 그대로 둡니다(`tools/codepatch.py`).

- **옮겨 넣기:** 재배치로 시작 주소만 참조되고 여유 패딩이 8바이트 미만인 문자열은 원래 칸을 비우고, 빈칸들을 모은 공간에 번역을 다시 채운 뒤 재배치 대상을 고칩니다.
- **공간 확보:** 공간이 모자라면 디버그 안내 문자열 칸을 비워 씁니다.
- **고정 칸:** 옵션 표 같은 구조체 안 고정 칸 문자열은 재배치 참조가 없습니다. 이런 문자열은 4바이트 정렬 안쪽 여유에 들어갈 때만 제자리에 씁니다.
- **원문으로 둔 것:** 한 단어 문자열은 게임이 열쇠로 쓰거나 상대 오프셋으로 참조하는 경우가 있어 원문으로 둡니다. 시험 삼아 모두 옮겼더니 로스터가 `[NONE]`이 되고 경기가 멈췄습니다. 옵션 값 몇 단어(Rookie, Veteran, Default, Meter, Night 등)만 허용 목록으로 제자리 치환합니다.

## 한글 인코딩과 글꼴

한글 음절에 번호 k를 매겨 2바이트 `0x80 | k>>7`, `0x80 | k&0x7F`로 씁니다. 1,089자를 씁니다(`tools/ktext.py`).

각 모듈의 글자 추가 함수(AddGlyph)를 부르는 세 곳에 훅을 넣었습니다. 훅은 선두 바이트와 다음 바이트를 묶어 코드 `0x100 + k`로 바꾸고, 짝이 없는 선두 바이트는 폭 0인 빈 글자로 처리합니다. 훅 코드는 `bal`로 자기 위치를 구해 재배치 없이 원래 함수로 점프합니다.

`tools/fontgen.py`는 원본 글꼴(`english`, `game`, `game2`의 bin+tx2)에 한글 글리프 레코드를 덧붙입니다.
- 글리프 인덱스는 `0xE0 + k`입니다.
- 폭을 재는 함수는 한글 바이트를 하나씩 대체 인덱스로 재기 때문에, 각 서브폰트에 "앞 서브폰트 한글 반 폭" 레코드를 둡니다.

이름 첫 글자 서식 `%c. %s`는 `%c\x01%s`로 바꿨습니다. `%c`가 한글 선두 바이트만 찍어 깨지는 것을 막습니다(0x01과 짝 없는 선두 바이트는 폭 0).

## 화면세트(UI 레이아웃)

WAD의 화면세트 파일은 `[u32 길이][문자열][NUL]` 레코드로 된 스트림이라 길이를 바꿔 다시 써도 됩니다(`tools/scr.py`). 표시 문자열 요소의 머리에는 다음 값이 있습니다.
- 위치·크기 `x, y, w, h`
- `04 02 01 ?? 01` 뒤에 글자 크기, 줄 간격, 줄바꿈 폭, 최대 줄 수

### 게임 팁

게임 팁 화면(`GT_*`)은 본문 요소가 둘 이상입니다.
- **영문:** 위 칸에 전체 문장을 넣고 최대 줄 수로 자릅니다. 그림 옆 칸에는 잘린 뒷부분을 따로 넣어 둡니다.
- **한글의 문제:** 게임의 줄바꿈 측정이 실제 폭보다 작게 나와 줄이 칸을 넘쳤습니다. 뒷부분 칸에는 마지막 문장이 겹쳐 나왔습니다.
- **해결:** `tools/gtips.py`가 칸마다 폭·줄 수를 읽습니다. 번역문을 `^n^`으로 직접 줄바꿈해 위 칸에 줄 수만큼 넣고, 나머지는 다음 칸에 넣습니다(34개 화면).

팁 창 버튼 줄의 테두리(`PS_ButtonBak`)는 영문 아이콘 위치에 고정돼 있어 한글 문구와 어긋나므로 알파를 0으로 숨겼습니다.

## 선수 이름과 머리 모델

로스터 파일(`PLR_PROFS` 등)의 선수 레코드는 79바이트이며 이름 16바이트, 성 16바이트가 붙어 있습니다(`tools/names.py`). 경기용 로스터(해시 `0x8382E1B8`)와 메뉴용 로스터 여러 벌을 모두 바꿉니다.

GAME 모듈 `0x14B48` 함수가 로스터 레코드로 선수 객체를 만듭니다.
- **+4:** `data/heads/<성>_<이름>/`(공백 `' . , \` -` 제거)
- **+0x44:** 표시용 `"%s %s"` 전체 이름
- **+0x84:** 유니폼 등 이름(성, 13자까지)

머리 파일은 +4 경로에 `PackFile.ps2`를 붙여 WAD에서 찾습니다. 그래서 이름을 바꾸면 머리를 찾지 못해 얼굴이 사라집니다.

**머리 별칭:** 한글 이름으로 만든 경로의 해시 항목을 WAD 디렉터리에 추가하고, 크기·오프셋은 원래 머리 파일과 같게 둡니다(1,821개).
- 디렉터리가 길어져 첫 데이터와 겹치므로, 겹치는 파일은 확장 영역으로 옮깁니다.
- 해시는 위의 대문자 변환을 그대로 따라야 맞습니다.

**유니폼 등 이름:** 등 이름은 영문 글자 텍스처로 그려서 한글 성은 깨진 글자로 나옵니다. 네 모듈의 해당 코드 `movn s1, v0, v1`을 `move s1, zero`로 바꿔 등 이름을 비웠습니다(등번호는 그대로).
